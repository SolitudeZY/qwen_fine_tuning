# Qwen 3.5 视频推理：超参数详解与误报优化策略

在使用 `video_infer_qwen35.py` 处理视频（特别是无人机等移动视角视频）时，大模型单帧推理极易受到镜头运动、视角偏远、光线变化的影响而产生误判。

为了应对这些挑战，脚本引入了多维度的超参数控制。本文档将详细解析这些参数的机制，并提供针对高误报场景的优化策略。

---

## 1. 核心超参数详解

### 1.1 `--diff-threshold` (帧差阈值)
- **作用**：控制“抽帧”时，画面发生多大程度的变化才触发大语言模型（LLM）重新推理。
- **机制**：计算当前帧与上一帧的灰度绝对差均值。若该值 `< diff_threshold`，脚本认为场景静止，直接复用上一帧的推理结论（合规/违规）；若 `>= diff_threshold`，才真正送入模型推理。
- **调参建议**：
  - **偏低（如 5.0）**：非常敏感。无人机稍微一晃动就会触发推理，导致推理次数多，且容易把因为移动模糊的帧送给模型，导致误报。
  - **偏高（如 25.0）**：变得“迟钝”。对于持续平移的无人机画面，系统会更多地复用之前的结论，不仅能大幅提升处理速度，还能有效避免模型对某些“刁钻/模糊角度”产生单帧误判。

### 1.2 `--window-size` (时间滑窗大小)
- **作用**：抗干扰机制，决定需要连续“多少帧”的确认，才最终抛出告警。
- **机制**：维护一个固定长度的队列。只有在这个队列中，超过 **50%** 的帧被模型判定为“违规”时，才会在最终的 JSON 报告中输出违规事件。
- **调参建议**：
  - **偏低（如 3）**：在 1 FPS 下代表 3 秒的滑窗。如果视频里有 2 秒的误报，就会直接告警。
  - **偏高（如 5 或 7）**：在 1 FPS 下代表 5 秒的滑窗。模型必须在连续 5 秒的画面里，至少有 3 帧判定违规才会告警。这能像滤波器一样，抹平绝大多数因为视角一晃而过导致的“偶发性误报”。

### 1.3 `--fps` (目标采样率)
- **作用**：从原始视频中抽取画面的频率，默认 `1.0`（每秒抽 1 帧）。
- **调参建议**：如果是快速飞行的无人机，建议调高至 `2.0` 甚至 `3.0`，同时配合调大 `--window-size`（如调到 `10`），以实现“密集采样 + 严格滑窗”，既不漏报也不误报。

## 2. 减少误报的综合策略

当您发现“12个报错里有一半是误报，主要是无人机视角看不清大桥护栏”时，建议按照以下优先级进行调整：

### 策略 A：修改时空降维参数（立竿见影，最推荐）
**动作**：增加滑窗大小和帧差阈值。
```bash
--diff-threshold 25.0 \
--window-size 5
```
**原理**：大桥护栏因为距离远，模型在某些帧容易“看不见”。将滑窗调到 5，模型就必须“连续多帧都确认没看到护栏”才会告警；同时 25.0 的阈值让镜头平移时不会频繁触发重新判断。

### 策略 B：通过 Prompt 进行文本干预（无需重训模型）
**动作**：在运行指令时加入自定义的 `--query`，提前给大模型“打预防针”。
```bash
--query "请检查图片中的临边是否存在护栏缺失。注意：这是无人机高空视角，大桥上的护栏可能显得细小模糊，只要能隐约看到连续的线条或阴影，请判定为合规，切勿误报。"
```
**原理**：Qwen 3.5 是大语言模型，能理解复杂的文本约束。通过告诉它“高空视角的特殊性”，让它在证据不足时倾向于判定为合规（保守策略）。

### 策略 C：数据反哺微调（治本之法）
**动作**：将本次推理中生成的 `alert_frames/` 文件夹里误报的图片（如远景大桥合规护栏被画了红框的截图）挑出来，去除红框（使用原始帧），打上“合规”的标签。
**原理**：模型之所以误报，是因为它的 Stage2 训练集中极度缺乏“无人机高空远景大桥护栏”的负样本（合规样本）。将其加入数据集再训练一个 Epoch，模型就能建立对该特定视角的认知。

### 策略 D：大图分块推理 (Tiled Inference)
**原理**：无人机视频分辨率通常是 1080P 或 720P，大桥远景护栏在整张图中占据的像素极少，在被 `Qwen-VL` 缩放送入视觉编码器时细节丢失。
**未来动作**：如果 A/B 策略都无效，您可以在 `video_infer_qwen35.py` 中引入 `tiled_infer.py` 的逻辑。将抽出来的帧切成 2x2 的子图，让模型去审视大桥局部的放大画面，这能极大提高小目标的识别率。
